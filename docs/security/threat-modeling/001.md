# STRIDE Threat Model

## Endpoint

`GET /api/v1/products/{id}`

### Descripción

Obtiene el detalle de un producto.

### Nivel de acceso

Público.

### Entrada

| Parámetro | Ubicación | Tipo |
|---|---|---|
| id | Path | UUID / Integer |

## Activos

* Información pública del producto.
* Información interna del producto.
* Disponibilidad de la API.
* Integridad de la base de datos.
* Logs y datos de observabilidad.
* Infraestructura del microservicio.

---

## STRIDE

| ID | Categoría | Amenaza | Impacto | Mitigación |
|---|---|---|---|---|
| S-01 | Spoofing | Falsificación de headers internos | Medio | Kong elimina o sobrescribe headers internos; el servicio no confía en headers proporcionados externamente |
| T-01 | Tampering | Manipulación del `id` | Medio | Validación estricta UUID/Integer y `400 Bad Request` para formatos inválidos |
| T-02 | Tampering | SQL Injection mediante el parámetro `id` | Alto | Uso de queries parametrizadas/JPA |
| R-01 | Repudiation | Imposibilidad de correlacionar una solicitud | Medio | Correlation ID y logs estructurados |
| I-01 | Information Disclosure | Exposición de campos internos del producto | Alto | DTO público con campos explícitamente permitidos |
| I-02 | Information Disclosure | Enumeración de productos | Medio | UUID cuando aplique, rate limiting y monitoreo |
| I-03 | Information Disclosure | Exposición de errores internos o stack traces | Medio | Manejo estandarizado de excepciones |
| D-01 | Denial of Service | Alto volumen de requests públicos | Alto | Rate limiting en Kong, timeouts y monitoreo |
| D-02 | Denial of Service | Consultas repetitivas generan sobrecarga de DB | Alto | Rate limiting, índices y caching donde aplique |
| E-01 | Elevation of Privilege | Exposición de productos no clasificados como públicos | Alto | Validar visibilidad/publicación antes de devolver el producto |

## Controles de Seguridad Requeridos

### API Gateway

Kong será responsable de:

* Rate limiting.
* Routing.
* Eliminación/sanitización de headers internos.
* Correlation ID.
* Métricas y observabilidad de tráfico.

### Product Service

El microservicio será responsable de:

* Validación de `id`.
* Validación de existencia del producto.
* Validación de que el producto pueda exponerse públicamente.
* Mapeo Entity -> Public Response DTO.
* Manejo de excepciones.
* Queries parametrizadas.

### Database

La base de datos deberá contar con:

* Índice sobre el identificador utilizado para consultar el producto.
* Usuario de aplicación con privilegios mínimos.
* Acceso restringido únicamente desde componentes autorizados.

## Respuestas esperadas

| Escenario | HTTP Status |
|---|---|
| Producto encontrado | `200 OK` |
| ID con formato inválido | `400 Bad Request` |
| Producto inexistente | `404 Not Found` |
| Producto no disponible públicamente | `404 Not Found` |
| Rate limit excedido | `429 Too Many Requests` |
| Error interno no controlable | `500 Internal Server Error` |

Para productos que existen pero **no son públicos**, se recomienda responder `404 Not Found` en lugar de revelar explícitamente su existencia.
